# Обновления из интерфейса для self-hosted установки

In-app updates позволяют администратору платформы увидеть опубликованную версию и запустить штатное обновление в **Настройки → Обновления платформы**. Первичную настройку всё ещё выполняет доверенный оператор сервера, но для обычных обновлений CLI на сервере больше не нужен.

## Перед началом

- Используйте поддерживаемый `docker-compose.yml` из репозитория `veriqorn-install`.
- Docker-хост должен находиться под контролем вашей организации.
- Регулярно создавайте резервные копии PostgreSQL и MinIO: миграция БД может сделать откат небезопасным.

## Одноразовая настройка

Скопируйте актуальный `.env.example` установки в `.env` и задайте уникальный секрет update-agent:

```env
PLATFORM_UPDATE_AGENT_TOKEN=замените-на-случайный-секрет-длиной-не-менее-32-символов
```

Генерируйте значение в используемой у вас системе управления секретами. Не переиспользуйте `JWT_SECRET`, пароль БД или секрет другой инсталляции.

Один раз запустите или пересоздайте установку, чтобы Docker создал локальный сервис `update-agent`:

```bash
docker compose --env-file .env -f docker-compose.yml up -d
```

Агент не публикует порт на хосте. Backend может обратиться к нему только во внутренней сети Docker Compose.

## Как обновить платформу

1. Войдите под пользователем с ролью администратора платформы.
2. Откройте **Настройки → Обновления платформы**.
3. Проверьте доступный release и release notes.
4. Нажмите **Установить обновление** и дождитесь статуса задачи.

Агент самостоятельно выбирает latest stable GitHub Release, скачивает только образы Veriqorn backend и frontend, фиксирует их immutable digest, обновляет `PLATFORM_VERSION`, пересоздаёт эти сервисы и ожидает health check backend. Volumes PostgreSQL и MinIO сохраняются.

## Безопасность и восстановление

Только update-agent имеет доступ к Docker socket. Такой доступ эквивалентен root-доступу к серверу: не публикуйте агент через порт хоста или reverse proxy. Доступ к `.env` должен быть только у доверенных операторов; при возможной утечке смените `PLATFORM_UPDATE_AGENT_TOKEN`.

Агент не выполняет автоматический rollback после неуспешного health check: release мог уже применить необратимую миграцию БД. Для ручного восстановления используйте backup и процедуру из [руководства по обновлению системы](./system-update-guide.md).
