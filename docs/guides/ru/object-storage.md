# Хранилище Amazon S3 и MinIO

Начиная с v0.2.35 администратор платформы может управлять хранилищем через **Settings → Storage** в Community и Enterprise.

## Настройка подключения

1. Сгенерируйте ключ шифрования на сервере:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

2. Добавьте его как `VERIQORN_STORAGE_ENCRYPTION_KEY` в `.env`, пересоздайте backend и примените миграции БД. Храните резервную копию ключа отдельно от базы данных.
3. Создайте приватный bucket AWS S3 в нужном регионе. В настройках укажите название подключения, регион, bucket, необязательный префикс, Access Key и Secret Key. Для временных учётных данных также нужен Session Token; срок их действия необходимо поддерживать вручную.
4. Нажмите **Check connection** для проверки записи, чтения и удаления тестового объекта.
5. Нажмите **Activate**. Приложение повторит проверку и начнёт направлять новые загрузки в это хранилище без перезапуска.

Для MinIO выберите соответствующего провайдера, укажите HTTP(S)-адрес сервера и существующий bucket. Сохранённые ключи шифруются и не возвращаются через API настроек.

Разрешите чтение, запись и удаление объектов внутри выбранного префикса, включая `.veriqorn-check/`. Multipart-загрузкам и bucket с KMS-шифрованием нужны соответствующие дополнительные права. До использования в production проверьте крупные вложения с вашей AWS-политикой. Скачивание и просмотр работают через авторизованные эндпоинты приложения; bucket должен оставаться приватным.

## Уже загруженные файлы

Активация влияет на новые загрузки. Старые файлы продолжают использовать своё подключение, а небольшие текстовые/JSON-вложения сохраняются в БД по прежним правилам. Сохраняйте прежние подключения, ключи доступа и исходный MinIO, пока на них ссылаются файлы. Автоматический перенос и обновление учётных данных IAM role выделены в следующие этапы.

## Новая установка без MinIO

Используйте Docker Compose 2.24.4 или новее и стандартный `.env` из инструкции по установке. Оставьте переменные MinIO для подстановки в базовый файл: overlay отключит соответствующие сервисы. Скачайте overlay и выполните:

```bash
curl -fsSLO https://raw.githubusercontent.com/Veriqorn/veriqorn/main/deploy/compose.s3.yml
docker compose -f docker-compose.yml -f compose.s3.yml up -d
```

До активации подключения вложения сохраняются в PostgreSQL. Для существующей установки применяйте overlay только после переноса всех файлов, ссылающихся на встроенный MinIO. В Enterprise примените `compose.enterprise.yml` перед `compose.s3.yml` и задайте `UPDATE_COMPOSE_FILES=/install/docker-compose.yml,/install/compose.enterprise.yml,/install/compose.s3.yml`.

API и порядок обновления описаны в [полной инструкции](https://github.com/Veriqorn/veriqorn/blob/main/docs/object-storage.md).
